# 05 复盘：最难的问题、收获、下一步

## 最难的问题

**1. 怎么保证“不编造”不只是写在提示词里。**
模型可以说“根据 D01……”然后给出一段 D01 里没有的话。只靠提示词约束无法验证。最后的做法是把结束动作也做成工具（`final_answer`），让答案变成结构化数据，再在代码里逐条核对：文档本轮读过没有、quote 是不是原文子串。校验不过先让模型改一次，再不过就降级。这样“错误引用”从“看模型发挥”变成了“代码保证”。

**2. 怎么区分“模型决策”和“写死的流程”。**
题目说固定分支和自动重试不算 ReAct。最初想在工具层做自动重试，后来去掉了：工具失败只返回 `ok=false`，重试还是放弃由模型决定。同理，循环里没有“先 search 后 read”的硬编码顺序。Mock 是例外，它本质就是规则，所以文档里明确标注它只验证流程。

**3. 改写问题的召回。**
“一年能休几天带薪休假”和原文“年休假（以下简称年假）5 天”字面重合很少。一开始加了同义词也召回不到，原因是 coverage 的分母把同义词权重也算进去了，同义词越多覆盖率反而越低。改成分母只算原查询词后解决。这个问题是测试 `test_paraphrase_hits_same_chunk_as_original` 失败时发现的。

**4. 测试期望写得太松会掩盖错误。**
case_05 一开始期望“答案包含 10”，Mock 回答的其实是“满 1 年不满 10 年 5 天”那一句，因为里面有“10 年”也通过了。后来改成整句引用分档规则，期望改成“年假 10 天”。教训：期望要写到能区分对错的粒度。

## 收获

- 结构化的结束动作 + 代码侧校验，是降低幻觉风险最直接的工程手段。
- 故障注入要支持“失败 N 次后恢复”，否则只能测到“失败就放弃”一条路径。
- “替换文档内容后结论是否跟着变”是很好的测试思路，能区分 Agent 是在读文档还是在背答案。

## 下一步

1. 用真实模型跑全部用例，把 `*.real.json` Trace 补进仓库，对比 Mock 和真实模型的路径差异。
2. 冲突类型扩展：除数值外，还有适用条件、适用人群不一致；文档里写了“本通知替代……”时应按优先级作答，需要补一份带替代声明的文档和对应用例。
3. 检索：BM25 + 向量混合召回，同义词表从人工维护改为离线挖掘。
4. 多次运行稳定性：真实模型同一用例跑 N 次统计通过率，而不是只跑一次。
5. 引用校验从“子串匹配”升级为“引用是否支持答案”的判断（例如答案里的数字必须出现在引用里）。
